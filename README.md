## 📌 프로젝트 소개

**Team Omok**은 Photon PUN2를 활용하여 제작한 실시간 멀티플레이 오목 게임입니다.

기본적인 오목 규칙뿐 아니라, 실제 네트워크 게임에서 자주 발생하는 다음 문제들을 해결하는 데 집중했습니다.

- 플레이어 매칭 및 룸 입장 동기화
- 코인토스를 통한 선공/후공 결정
- 턴 기반 돌 배치 동기화
- 제한 시간 초과 시 자동 착수
- 금수 및 쌍삼 판정
- 게임 종료 후 재시작 및 리매치 처리
- 플레이어 퇴장 및 재접속 상황 대응
- 네트워크 지연으로 인한 중복 실행 방지

## 🧩 개발 핵심 포인트

### 1. Photon 기반 턴 동기화

오목은 한 명씩 번갈아 착수하는 구조이기 때문에,  
각 클라이언트의 턴 상태가 어긋나면 게임 진행이 불가능해집니다.

이를 해결하기 위해 다음 방식으로 동기화 구조를 구성했습니다.

- MasterClient 기준 주요 판단 처리
- RPC를 통한 돌 배치 결과 동기화
- RaiseEvent를 통한 게임 이벤트 전달
- 중복 착수 및 중복 이벤트 실행 방지
- 게임 종료 후 입력 차단

### 2. 네트워크 지연 대응

멀티플레이 환경에서는 두 클라이언트의 화면 상태가 항상 동시에 바뀌지 않습니다.  
따라서 단순히 로컬 변수만으로 상태를 판단하면 코인토스, 게임 시작, 리매치 시점에서 상태가 꼬일 수 있습니다.

이를 방지하기 위해 다음 처리를 적용했습니다.

- 룸 상태와 플레이어 상태를 Photon Custom Properties로 관리
- 씬 재로드 후에도 유지되는 서버 기준 상태 사용
- 게임 시작, 리매치, 결과 처리 시점에 상태 검증 추가
- 중복 실행 방지용 플래그 및 가드 로직 적용

### 3. 리매치 안정화

기존에는 리매치 여부를 로컬 변수로 관리했기 때문에,  
씬이 다시 로드되거나 한쪽 플레이어가 먼저 진입할 경우 상태가 초기화되는 문제가 있었습니다.

이를 개선하기 위해 리매치 상태를 Photon 서버에 저장하고,  
양쪽 플레이어가 모두 리매치를 요청했을 때만 다음 게임으로 넘어가도록 수정했습니다.

## 🚀 실행 방법

```bash
1. Unity 프로젝트를 실행합니다.
2. Photon App ID 설정을 확인합니다.
3. Start Scene을 실행합니다.
4. 로비에 입장합니다.
5. 매칭이 완료되면 게임이 시작됩니다.
```

## 📝 커밋 컨벤션

기본적으로 Conventional Commit 형식을 사용하며,  
Jira 이슈와 연결되는 작업은 이슈 번호를 함께 작성합니다.

```bash
feat: 제한 시간 자동 착수 추가
fix: 재접속 시 게임 상태 복구 수정
refactor: RPC 동기화 구조 개선
```

### Jira 연동 예시

```bash
feat(SCRUM-170): 재접속 동기화 추가
fix(SCRUM-171): 중복 시작 버그 수정
```

## ✅ 프로젝트 목표

Team Omok은 단순히 오목 규칙을 구현하는 것에서 끝나지 않고,  
실시간 멀티플레이 게임에서 중요한 **상태 동기화, 예외 처리, 재접속 안정성**을 직접 구현하는 것을 목표로 했습니다.

이를 통해 Photon 기반 네트워크 게임 개발에서 필요한 다음 경험을 쌓았습니다.

- 룸 기반 멀티플레이 흐름 설계
- MasterClient 기준 권한 처리
- RPC / RaiseEvent 기반 이벤트 동기화
- 네트워크 지연 상황에서의 상태 검증
- 게임 종료, 리매치, 재접속 시 상태 복구
- 팀 단위 Git / Jira 협업 프로세스 경험

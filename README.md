# 🎮 Team Omok

> Unity + Photon PUN2 기반 실시간 멀티플레이 오목 프로젝트

Team Omok은 Photon PUN2를 활용하여 제작한 실시간 멀티플레이 오목 게임입니다.  
기본적인 오목 규칙 구현을 넘어, 멀티플레이 환경에서 발생하는 **턴 동기화, 룸 상태 관리, 재접속, 리매치, 예외 처리**를 안정적으로 구현하는 것을 목표로 개발했습니다.

## 📌 프로젝트 소개

**Team Omok**은 2명의 플레이어가 실시간으로 대전할 수 있는 온라인 오목 게임입니다.

Photon PUN2 기반 네트워크 구조를 사용하여 룸 매칭, 선공 결정, 턴 진행, 돌 배치, 승패 판정, 리매치 흐름을 동기화했습니다.  
또한 플레이어 퇴장, 재접속, 네트워크 지연 등 멀티플레이 환경에서 발생할 수 있는 예외 상황을 고려하여 게임 흐름이 깨지지 않도록 안정화 작업을 진행했습니다.

## 🧩 기술적 특징

### Photon 기반 네트워크 동기화

오목은 한 명씩 번갈아 착수하는 턴 기반 게임이기 때문에,  
각 클라이언트의 턴 상태와 돌 배치 결과가 일치해야 합니다.

이를 위해 주요 게임 판단은 MasterClient 기준으로 처리하고,  
RPC와 RaiseEvent를 활용하여 모든 클라이언트에 동일한 게임 결과가 반영되도록 구성했습니다.

### 서버 기준 상태 관리

멀티플레이 환경에서는 씬 재로드, 플레이어 퇴장, 네트워크 지연으로 인해  
로컬 변수만으로 게임 상태를 관리하면 동기화 문제가 발생할 수 있습니다.

이를 방지하기 위해 Photon Custom Properties를 활용하여  
룸 상태와 플레이어 상태를 서버 기준으로 관리했습니다.

### 리매치 안정화

게임 종료 후 리매치 과정에서 한쪽 플레이어가 먼저 씬에 진입하면  
로컬 상태가 초기화되어 게임 흐름이 어긋나는 문제가 발생할 수 있습니다.

이를 해결하기 위해 리매치 요청 상태를 Photon Custom Properties로 저장하고,  
양쪽 플레이어가 모두 리매치를 요청했을 때만 다음 게임으로 진행되도록 구성했습니다.

### 중복 실행 방지

네트워크 지연이나 빠른 입장 처리로 인해 코인토스, 게임 시작, 착수 로직이 중복 실행될 수 있습니다.

이를 방지하기 위해 게임 시작 상태, 코인토스 진행 상태, 게임 종료 상태를 검증하는 가드 로직을 적용했습니다.

## ✅ 프로젝트 목표

Team Omok은 단순한 오목 게임 제작이 아니라,  
실시간 멀티플레이 환경에서 발생하는 다양한 상태 동기화 문제를 직접 해결하며  
안정적인 네트워크 게임 구조를 구현하는 것을 목표로 했습니다.

이를 통해 다음과 같은 개발 경험을 쌓았습니다.

- 룸 기반 멀티플레이 흐름 설계
- MasterClient 기준 권한 처리
- RPC / RaiseEvent 기반 이벤트 동기화
- Photon Custom Properties 기반 상태 관리
- 네트워크 지연 상황에서의 상태 검증
- 게임 종료, 리매치, 재접속 시 상태 복구
- 팀 단위 Git / Jira 협업 프로세스 경험
